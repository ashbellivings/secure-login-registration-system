1. Cryptographic Password Hashing (Bcrypt)

CIA: Confidentiality · NIST SP 800-63B
What the Control Is
A one-way cryptographic hashing function incorporating a unique 128-bit salt and an adjustable computational cost factor (12 rounds) applied before writing credentials to the database.
Why It Is Required & Risk Addressed
Prevents credential compromise if the database is leaked. Plaintext passwords are never stored. Defends against offline dictionary and pre-computed rainbow table attacks.
Implementation Location
routes/authRoutes.ts (line 104) using bcrypt.hash(password, 12); schema definition in models/User.ts.
Audit Evidence & Testing
Inspect MongoDB documents. Every stored password matches the modular crypt format $2a$12$... or $2b$12$.... Test 1.6 & 5.1 verify this automatically.

2. User Authentication & Side-Channel Defense

OWASP ASVS V2 Authentication
What the Control Is
Verification of user identity at login via bcrypt.compare(), paired with a constant-time dummy compare for non-existent users and generic error responses.
Why It Is Required & Risk Addressed
Prevents account takeover. Eliminates timing attacks and user enumeration where attackers determine valid accounts by analyzing response time differences.
Implementation Location
routes/authRoutes.ts lines 162–186. Constant-time dummy hash: DUMMY_HASH. Generic response: "Invalid email or password."
Audit Evidence & Testing
Submit incorrect password and nonexistent email; both return identical HTTP 401 with identical response bodies. Automated tests 2.1, 2.2, 2.3 verify this.

3. Server-Side Authorization & Access Control

CIA: Confidentiality & Integrity · Least Privilege
What the Control Is
Mandatory server-side middleware (requireAuth) that verifies session presence and derives identity exclusively from the server session record in MongoDB.
Why It Is Required & Risk Addressed
Prevents unauthorized access to private profiles and Insecure Direct Object Reference (IDOR) attacks where a user changes an id parameter to view another account's data.
Implementation Location
middleware/authentication.ts lines 23–52; mounted on /api/profile in routes/profileRoutes.ts.
Audit Evidence & Testing
Send GET /api/profile without cookies; backend returns HTTP 401. Send with arbitrary query ?userId=123; server ignores parameter.

4. Session Management & Session Fixation Mitigation

OWASP ASVS V3 Session Management
What the Control Is
Express-session backed by MongoDB (connect-mongo) with automatic session regeneration (req.session.regenerate()) upon successful login.
Why It Is Required & Risk Addressed
Prevents session fixation where an attacker traps a victim into using a known session token. Prevents token storage in vulnerable browser localStorage.
Implementation Location
server.ts lines 58–75; routes/authRoutes.ts line 191.
Audit Evidence & Testing
Compare Set-Cookie header values before and after login; the session identifier is replaced with a fresh token. MongoDB sessions collection stores active sessions.

5. Cookie Security Attributes (HttpOnly, SameSite, Secure)

Defense-in-Depth · XSS & CSRF Mitigation
What the Control Is
Session cookies are marked with HttpOnly: true, SameSite: Lax, and Secure: true (in production HTTPS).
Why It Is Required & Risk Addressed
HttpOnly prevents client-side JavaScript (e.g. injected XSS payloads) from reading document.cookie. SameSite: Lax prevents cross-site request forgery.
Implementation Location
server.ts lines 67–73 (session cookie configuration object).
Audit Evidence & Testing
Open browser DevTools Console and execute document.cookie. The connect.sid session cookie is not visible. Inspect network response headers for flags.

6. Rate Limiting & Brute-Force Prevention

CIA: Availability & Integrity · OWASP Rate Limiting
What the Control Is
Sliding window rate limiters configured via express-rate-limit: 20 authentication attempts per 15 minutes for /api/login and /api/register.
Why It Is Required & Risk Addressed
Slows down automated password-guessing, credential stuffing dictionaries, and denial-of-service attempts without locking out user accounts permanently.
Implementation Location
middleware/security.ts lines 6–18; applied to auth endpoints in routes/authRoutes.ts.
Audit Evidence & Testing
Response includes RateLimit-Limit and RateLimit-Remaining HTTP headers. Exceeding threshold triggers HTTP 429 Too Many Requests.

7. Secure Secrets Management & Least Privilege

Operational Security · OWASP Top 10 A05
What the Control Is
All sensitive credentials (MONGODB_URI, SESSION_SECRET) are stored in server-side environment variables loaded via dotenv.
Why It Is Required & Risk Addressed
Prevents hardcoded credentials in source code. .gitignore explicitly blocks .env files from being pushed to public version control repositories.
Implementation Location
.env.example, .gitignore, server.ts. Database passwords in logs are masked with ***:*** in config/database.ts.
Audit Evidence & Testing
Git repository scan verifies that zero credentials exist in committed code; .env.example provides clear placeholders without secrets.

8. HTTP Security Headers & Defense-in-Depth (Helmet)

Browser Security Controls
What the Control Is
Express security middleware enforcing Content Security Policy (CSP), X-Content-Type-Options: nosniff, X-Frame-Options: SAMEORIGIN, and removal of X-Powered-By.
Why It Is Required & Risk Addressed
Mitigates MIME-sniffing vulnerabilities, clickjacking attacks, unauthorized cross-origin script execution, and backend software fingerprinting.
Implementation Location
server.ts lines 31–46 using helmet().
Audit Evidence & Testing
Inspect HTTP response headers via browser Network tab or curl: x-content-type-options: nosniff is present; x-powered-by is absent.

9. Safe Error Handling & Information Leakage Prevention

OWASP ASVS V13 Error Handling
What the Control Is
Centralized error handling middleware intercepting all unhandled exceptions and returning structured JSON with sanitized user-facing messages.
Why It Is Required & Risk Addressed
Prevents information leakage (stack traces, SQL/NoSQL query fragments, file paths, database connection strings) that assist attackers in crafting exploits.
Implementation Location
middleware/errorHandler.ts mounted as the final middleware in server.ts.
Audit Evidence & Testing
Trigger a duplicate key or malformed JSON payload; verify the response contains only clean error messages without call stacks or database exception internals.
